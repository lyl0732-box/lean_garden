## 1：第九关增加后继目标

自然数第九关仍使用稳定 ID `n06`，条件仍为 `h : a = b + 1`，目标改为 `a + 0 = succ b`。参考路线依次使用 h、add_zero、add_one_eq_succ，再手动 rfl，不能仅靠消去 +0 结束。没有删减关卡或改变归纳关序号；总数仍为 113。

## 2：修复第十三关的 rfl

按 [原始截图](../任务清单/13关badcases.png)复现了替代解法：对 h 使用后继单射，再反向改写目标，得到画面中的 `a = a`，此前严格 rfl 错报「只能用于等式」。

改写产生的目标在内部可能包着已应用的 lambda。严格 rfl 现在先展开这一层 beta 表达式并去除元数据，再检查可见等式。不会借此计算加法或展开其它定义。真实接口和浏览器均验证了上述替代解法；`0+0=0` 直接 rfl 仍被拒绝。

## 7：启动预加载与弱网资源

- 启动先显示实际下载进度，按资源字节更新百分比；完成下载与图片预解码后才进入序章或游戏。
- 预先准备所有对局卡片、两幅主背景、代码／样式和七首 BGM。正常模式约 27.4 MiB；弱网、省流模式约 13.9 MiB，降低背景分辨率和音频码率，矢量知识卡保持清晰。
- 七首音乐使用本地 Blob 播放，卡片和背景也使用本次预加载资源。浏览器验证进入后的对局、花园和音乐切换没有新增图片或音频下载。
- 安全来源可使用持久 Cache Storage；普通 HTTP 来源使用浏览器缓存与本次会话资源，不强依赖 Service Worker。失败会重试，自动模式还可转为流畅资源；错误界面保留重新准备入口。
- 原有内容策略增加对图片与音频 Blob 的支持，脚本来源限制继续保留。音效由 Web Audio 合成，代码也已包含在预加载中。
- 高低码率 MP3 为原曲转码版本，原文件在本机保留；署名和转码说明已同步至 [音乐文档](../docs/MUSIC.md) 与授权文件。

资源清单为 `public/assets/preload-manifest.json`，生成命令 `npm run build:assets`；只修改代码后用 `npm run build:manifest` 更新哈希与字节数。
